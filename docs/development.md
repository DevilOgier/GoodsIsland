## 当前状态

仅完成设计文档和仓库基础文件。按原始需求先等待设计确认，之后再生成应用、Prisma Schema 和 migration。下面均为实施计划，非已执行测试记录。

|P0-7 图片|S3 直传、Sharp、任务、Mock、Topaz、原图对比|上传校验、增强失败保留原图/旧版、超时恢复、真实 provider 可配置联调|

每模块固定执行：实现 → typecheck → lint → unit → migration（有模型变化时）→ integration。业务 migration 随模块增量提交；禁止一次生成大批功能后跳过验证。真实 provider 无密钥时只验证 Mock/契约测试，报告真实联调未完成，不能算作真实增强通过。

## 测试矩阵

- BUY +3、SELL -1，库存 2；库存 2 卖 3 失败且无 Sale/Event 残留。
- 挂出 2 时库存 3；成交 1 后库存 2/挂出 1；再次导出不改变任何数量。
- 并发卖出和重复 arrive；数据库断点失败全部回滚；校验 `SUM(delta)=cache`。
- 总成本 10 元分 3 次卖完，分摊总和精确等于 10；后续买入移动均价；零库存成本归零。
- 未到货不入库；到货一次；已取消不能到货；已入库不得改原始成本。
- Group 含 A×2/B×1/C×3，支付、上游运输、排发及本人到货独立可见。
- Wanted 不持有也能建；仅完成状态不自动买入；组合收到正确事务入库。
- 两用户同商品独立库存；跨用户 ID 操作失败；USER 写公共图鉴失败。
- 原图 checksum 在增强成功/失败后不变；新图上传后旧任务完成不覆盖；worker 租约过期能恢复。
- 海报五比例×四模板，中文长名、空图、透明图、可议价、超容量；重复 SVG 完全相同；PNG/JPG 在固定浏览器验收。
- 375/390/430/768/1024/1440px 检查商品卡、详情、库存、团详情、海报编辑、上传、筛选和底栏；横向无溢出，焦点与键盘可用。
- PWA 生产构建安装、离线页、SW 升级、登出后不留私有缓存。

## Git 工作流

当前目录作为本地 Git 仓库，主分支 main。设计以 `docs: define v1 architecture and data model` 首次提交；后续每模块用 `feat/catalog`、`feat/inventory` 等短分支，独立提交可审查成果。commit 前查看 diff、运行相应检查；不将未通过测试的代码称为可发布。

提交使用 feat/fix/docs/test/chore 前缀。Schema 和对应 migration、必要测试同一提交；记录破坏性迁移操作。密钥、.env、数据库备份、模型权重、用户图片和构建产物忽略；.env.example 仅空值或明确占位符。保留锁文件。

首次提交使用当前已配置 Git 身份，不擅自伪造作者。如果没有身份则保留待提交工作并说明。远程仓库尚未指定，不自动创建公开仓库或推送；指定远程后再配置 origin 和推送。上线前给通过验收版本打 v0.1.0 标签。

## 本地/部署计划

实施后提供可复制启动命令和锁定版本。Docker 多阶段构建 web；worker 用相同源码/依赖，单独入口；Compose 提供健康检查、数据库持久卷及开发对象存储。生产启动前运行 `prisma migrate deploy` 独立步骤，不让多个 web 实例同时迁移。

对象存储按开发/生产分 bucket，配置精确浏览器 Origin CORS；密钥有 bucket 最小权限。临时 presigned URL 不进入日志。生产启用 TLS 和安全 cookie。Session 可撤销，初始化管理员不写固定密码到种子。

备份同时覆盖 PostgreSQL 和对象存储；仅备份 DB 无法恢复图片。发布前测试恢复；部署回滚优先回滚应用，数据库破坏性变更采用兼容迁移，避免盲目 down migration 丢数据。

## 完成标准

用户能登录维护图鉴，买入→到货→库存→挂出/收物→生成海报→真实成交形成完整链路；所有要求页面可用；图片增强与原图可独立追踪；关键业务、PWA、响应式和 Docker 验证通过。直到这些条件满足才可标记 V1 完成。
