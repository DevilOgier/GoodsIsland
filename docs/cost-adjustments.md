# 已确认变更：晚补运费立即支持

2026-09-08 用户确认其他推荐方案，并要求晚补运费纳入 V1。本文件取代旧 D4“入库后成本锁定”的限制。

购买后任何阶段（取消除外）可追加国内运费、国际运费、其他费用，必须填写原因；保存 FeeAdjustment，不覆盖历史费用记录。购买总费用展示初始费用加历次追加，actualCost 同事务更新。V1 追加非负费用；退款属于另一业务。

未到货追加只更新购买成本。已到货追加：锁住该商品库存，按稳定 sequence 重放移动平均成本，以每笔购买当前 actualCost 重算入库价值。后续每次出库分摊重新计算；原始 Sale 成本不改，追加 SaleCostAdjustment 差额；原始 InventoryEvent 不改，新增 quantityDelta=0 的 COST_ADJUSTMENT 记录剩余库存价值差额。CostRevision 保存每笔出库重算结果。上述操作及 FeeAdjustment 同一事务提交。

例：买3件30元，卖1件15元，后补国际运费6元。采购成本36元，已售成本从10调整到12，利润从5调整为3，剩余库存成本从20调整到24。全部售出后补费，库存仍0，费用反映到历史已售成本。多批买入按原入库顺序重放。

用户主动修正或删除买入记录时，系统按 InventoryEvent.sequence 重新计算该商品的全部库存与出库成本。修改已入库记录会同步修改对应 BUY 数量和成本；改回待到货会撤销 BUY；删除记录会移除对应 BUY 和该记录的补费。若重放到某笔历史出库时数量不足，事务整体拒绝并保留原数据。关联拼团的团内商品保留并回到可重新登记购买的状态。

本地 PostgreSQL 和 S3 兼容开发服务只监听 loopback，数据在忽略目录 .local 持久化。未来迁移数据库与对象数据后修改 DATABASE_URL、APP_URL、S3 配置；仅换URL不会搬迁数据。
